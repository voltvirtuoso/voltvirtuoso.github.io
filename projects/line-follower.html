PID Line-Following Robot

A constrained-path robot that holds its line using a carefully tuned PID controller, with dedicated logic for sharp turns and an auto-calibrating sensor array.

A constrained-path robot that uses a tuned PID controller to hold its line, built as a hands-on exercise in sensor feedback, error correction, and iterative tuning — including four rounds of gain and behaviour tuning on the way to a stable controller.

Overview

Line-following looks trivial until the robot has to hold a line through a sharp turn without overshooting or oscillating. This project used it as a focused control-systems exercise: read the line-position error from a six-sensor array, feed it through a tuned PID controller, and adjust motor output continuously rather than reacting to fixed thresholds. Getting there took several iterations — the working firmware is version four of the controller, with each earlier pass tuning gains, calibration behaviour, or the sharp-turn logic before landing on a stable combination.

Key features

  • Auto-calibrating threshold — on startup, the robot spins in place for 3000 iterations, records the min/max reading on each of six sensors, and sets each threshold to the midpoint, so it adapts to the actual line and surface instead of a hardcoded value.
  • PID error correction — for the general case, the error is the difference between the two outer-middle sensors, mapped to a 0–255 range and fed through a proportional-integral-derivative loop to bias the two motors in opposite directions.
  • Dedicated sharp-turn handling — hard left/right turns and a three-sensor "junction" case are handled as explicit states, spinning the robot until the line reappears, rather than trusting the PID loop to recover a turn that sharp on its own.
  • Custom motor driver — a small Motor class wraps each H-bridge channel, clamping drive values to ±255 and switching direction by driving one pin with PWM while holding the other low.
Tuning lesson

Each version in the project history changed one thing at a time — max speed, then the calibration drive power, then the turn-handling logic, then adding dt back into the derivative term. Isolating each change made the controller's behaviour predictable instead of a matter of trial and error.

Tech stack

A six-sensor analog array (A0–A5) feeds an Arduino-class microcontroller running the PID loop, which drives two DC motors through a simple H-bridge interface — a small, self-contained closed-loop system with no external dependencies beyond the Arduino core.

Implementation

The motor driver takes a signed value and turns it into a PWM-plus-direction pair, clamping to the analogWrite range:

class Motor{
  int pos, neg;
  public:
  void pin_selection(int motor_pos, int motor_neg){
    pos = motor_pos; neg = motor_neg;
    pinMode(pos, OUTPUT); pinMode(neg, OUTPUT);
  }
  void drive(int value){
    if (value >= 0){
      if (value > 255) value = 255;
      analogWrite(pos, value); digitalWrite(neg, LOW);
    } else {
      if (value < -255) value = -255;
      analogWrite(neg, -value); digitalWrite(pos, LOW);
    }
  }
};

The PID function itself tracks elapsed time between calls so the derivative term is a true rate of change, not just a frame-to-frame delta:

double pid(double error){
  double now = millis();
  dt = (now - last_time) / 1000.00;
  last_time = now;

  double proportional = error;
  integral += error;
  double derivative = (error - previous) / dt;
  previous = error;
  return (kp * proportional) + (ki * integral) + (kd * derivative);
}

In the final tuning pass, gains settled at kp = 0.35, ki = 0, kd = 17, with a base speed of 80. The main loop checks for the two hard-turn cases and the three-sensor junction case first — each spins the robot at a fixed speed until the line reappears under the centre sensor — and only falls through to the PID correction for the ordinary case of gently drifting off-centre:

if (isBlack(1) && isBlack(2) && isBlack(3)) {
  // hard left: spin until the line reappears
  motor1.drive(80); motor2.drive(-80);
  while(true){ if(isWhite(1) && isWhite(2) && isBlack(3)) break; }
}
else if (isBlack(5) && isBlack(4) && isBlack(3)) {
  // hard right: mirror of the above
  motor1.drive(-80); motor2.drive(80);
  while(true){ if(isWhite(5) && isWhite(4) && isBlack(3)) break; }
}
else {
  // ordinary case: PID correction around centre
  int error = map(analogRead(pins[4]), 0, 1024, 0, 255)
              - map(analogRead(pins[2]), 0, 1024, 0, 255);
  double val = pid(error);
  leftm_speed  = max_speed + val;
  rightm_speed = max_speed - val;
}

Outcome

The finished robot could hold a line through turns that a purely proportional response would overshoot, handling sharp corners as explicit spin-until-found manoeuvres rather than asking the PID loop to do more than it reasonably could. The tuning history — four labelled versions in the source file, each changing one variable at a time — turned out to be as instructive as the final result: isolating max speed, calibration power, turn logic, and the derivative term one at a time made an otherwise fiddly control problem tractable.
